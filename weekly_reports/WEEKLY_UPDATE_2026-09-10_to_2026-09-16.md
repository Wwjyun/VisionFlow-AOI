## 本週重點整理

- GPU mode 從「整圖 resident、部分 preprocessing 在 device」推進至 Template Anchor Grid、202 候選抽取、connected components、ring CNR 與必要統計可留在 device，並把傳輸降至每張一次整圖 H2D 與 22,340 bytes D2H。
- I/O 與控制面成本同步處理：BMP 平行讀取、file-order upload 避免 639 MB host 翻列、provenance 快取移除每張圖重複 Git subprocess；正式尺寸合成基準最終記錄 13.71× 端到端加速。
- CUDA 改動維持 ABI v1 optional-export 相容策略；舊 DLL 缺少新 export 時仍可回到既有上傳／CPU fallback，sticky device error 則停用 CUDA 直到程式重啟，避免每張圖持續重試失敗。
- v1.6.0 與 v1.6.1 為同日過渡版本；v1.6.2 已整合後續 anchor 修正、202 device-resident pipeline 與 BMP 路徑，應作為本週對外使用的版本基準。

## 版本差異與風險

- v1.6.0 發行版的 resident 模式實際未呼叫 GPU anchor，且 `device_host_split.anchor_localization` 會誤報為 device；此問題已於 v1.6.1 修正，判讀舊版結果時應以 `gpu_metrics.functions` 為準。
- v1.6.2 的 13.71× 效能與 3/3 判定一致性來自固定 seed 合成大圖與 RTX 3090／CUDA 13.3／`sm_86`；release notes 明示真實產線影像、判定門檻、其他 GPU 與無 GPU 電腦仍需目標環境驗收，不能把合成 benchmark 擴張為量產 acceptance。
- `Todo.md` 仍記錄共用 session 下 `device_host_split` 與 `execution.gpu.metrics` 使用累計值的觀測風險；單輪未呼叫某 export 時，先前輪次的累計可能使該步驟仍顯示 device，需改成每輪差值並補回歸測試。
- GPU contour operator 雖完成等價性探索，但量測後仍慢於 OpenCV，未接入 production；401-2 white-pixel GPU 化亦依使用情況暫緩。報告應區分「已驗證 operator」、「已接線路徑」與「僅完成研究／原型」。
- v1.6.2 為 CUDA-enabled、未簽章 Windows x64 發行包，DLL 針對 `sm_86` 驗證；不相容或沒有 NVIDIA GPU 時應使用 CPU 或允許 fallback 的模式，SmartScreen 亦可能顯示未知發行者。
